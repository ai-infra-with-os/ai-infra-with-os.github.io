with Operating Systems

A half-day tutorial on the systems software beneath modern AI, co-located with ACM SIGOPS ATC 2026 in Hong Kong.

Overview

The proliferation of large language models, AI agents and embodied intelligence is reshaping the interaction paradigm between humans, devices and computing systems. This shift calls for rethinking OS primitives, kernel abstraction, and system software stacks for AI-native workloads. Today's mainstream operating systems are still designed around application-centric abstractions and human-driven interaction, which creates fundamental mismatches for AI-native workloads: the lack of unified management abstraction for heterogeneous accelerators, inefficient GUI-based agent execution, coarse-grained permission mechanisms for cross-application data flows, lack of system-level resource orchestration for heterogeneous edge-cloud inference, and insufficient deterministic guarantees for mission-critical intelligent scenarios. Addressing these mismatches requires re-examining core infrastructure concerns — CPU/GPU/NPU scheduling, memory management, I/O and data movement, virtualization and isolation, runtime and serving systems, and compiler-system co-design — through an OS lens.

This tutorial aims to bring together researchers, engineers and practitioners from operating system, cloud computing, edge AI, agent systems and embedded computing communities, to discuss the architectural evolution of operating systems for the intelligent world. We will examine core challenges including heterogeneous system resource management, LLM serving, agent-native system abstraction, end-cloud collaborative inference runtime, deterministic convergence of intelligent workloads, and security & privacy for pervasive AI agents, and share practical experiences from real-world deployments on cloud, servers, wearables, and smart terminals.

Rethinking Memory Management for LLMs: Sparse, Addressable Model State as an OS Resource

Large language models are now a dominant systems workload, yet the way they manage their own memory is at odds with how operating systems manage theirs. Full attention keeps an unbounded KV cache that strains memory capacity and bandwidth; linear attention and state-space models fix the state size but collapse all history into a single dense matrix that is read and rewritten in full at every step, so unrelated tokens interfere and long-range recall degrades. Neither gives the system beneath it an addressable, partitionable resource. This talk presents RAM-Net, a linear-time sequence model whose recurrent state is a fixed-size array of independent slots accessed through sparse, content-derived addresses — a deliberate echo of how RAM is addressed in a computer. RAM-Net maps each key or query into a sparse address, selecting a small subset of slots to write to or read from at each step. This design directs tokens with non-overlapping addresses to disjoint slots, suppressing inter-token interference, while keeping per-step overhead dependent only on the number of accessed slots rather than the total state size. RAM-Net shows a clear advantage over strong linear baselines on fine-grained long-range retrieval and remains competitive on standard language modeling and commonsense reasoning, while accessing far fewer state elements per step than these baselines (e.g., 32X fewer than Mamba2). Lastly, we will discuss managing model state as a first-class OS resource and close by asking whether future kernels should expose abstractions for model memory as they do for virtual memory today.

Building Real-Time Robotic Operating System (ROS)

Embodied intelligence—robots that perceive, reason, and act in the physical world—is rapidly emerging as the next frontier of AI, increasingly powered by foundation models for perception, planning, and control. Unlike purely digital AI, embodied agents operate in closed feedback loops with the physical world: sensing, reasoning, and actuation must complete within timing constraints dictated by the dynamics of the environment, or the robot's actions will simply come too late. Robot Operating System (ROS) is the de facto software infrastructure underlying most of these systems, valued for its modularity and composability, which allow developers to assemble sophisticated behaviors by reusing existing packages. Yet this very design—and the co-location of heavy model inference with real-time control loops—makes end-to-end timing and predictability difficult to reason about and guarantee. This tension between AI capability and real-time reliability is a central bottleneck for deploying embodied agents in safety-critical, real-world settings. In this talk, I will identify the theoretical and practical challenges of building real-time software on ROS in the era of embodied AI, and introduce our recent work on establishing a theoretical foundation for, and improving the real-time performance of, ROS as dependable infrastructure for embodied intelligence.

A Display-Centric Process Model for Fast UI Responsiveness on Touchscreen Android Smartphones

Current Android display systems suffer from performance inefficiencies because their computation-centric process model treats display management as a secondary function. As a result, input and display operations traverse multiple software layers and user-space system services, incurring substantial communication overhead and degrading UI responsiveness. We advocate a display-centric process model built around process-level display management, where display becomes a first-class concern of the process model. In this tutorial, I will introduce our work on improving UI responsiveness by restructuring the display stack and distributing the functionality of conventional system services between the Linux kernel and individual application processes. In the kernel, a Screen Manager directly dispatches input events and composites display buffers; within each application process, dedicated memory regions and shared libraries enable unmodified applications to consume input and submit frames without involving user-space system services. This kernel-application co-design removes redundant IPC and context switches from the critical path. Our Android 14 prototype reduces end-to-end input latency by 90.91% and display latency by 87.93%, while lowering CPU and memory usage and substantially improving scalability as the number of concurrent applications increases.

Optimizing LLM at the Edge: From Inference and Fine-Tuning to Embodied Systems

Large language models deployed on mobile and edge devices face three constraints: memory, compute, and latency. This talk is organized into three parts—inference optimization, fine-tuning optimization, and on-device embodied systems. In inference optimization, we introduce a hierarchical coordination framework that selectively offloads attention computation and enforces per-layer sub-deadline scheduling, trading a controlled accuracy loss for real-time responsiveness; we also interleave multiple workflows at tile granularity and optimize engine scheduling to saturate mobile NPU throughput. In fine-tuning optimization, we adaptively balance recomputation against compression based on tensor characteristics to break through memory limits, and we design a unified tensor layout that serves both forward and backward passes, eliminating costly layout conversions and accelerating fine-tuning. We then turn to embodied scenarios exemplified by on-device Physical AI (VLA/WAM), present our inference acceleration work for such settings targeting iterative action generation, and conclude that optimizing edge large language models requires moving beyond isolated acceleration toward co-designing workload characteristics, hardware constraints, and scheduling strategies.

Fingerprinting and Watermarking LLMs for Trustworthy AI Ecosystems

Two major trust-related questions arise frequently in today's AI service ecosystem: (1) Can a user verify that an API serves the model it claims to serve? (2) Given an artifact, was it generated by a human or by AI (and by which model)? These two questions motivate the study of model fingerprinting and watermarking. This talk presents constructions for both research topics. For model fingerprinting, we present KBF, which uses patterns of factual recall near a model's knowledge boundary to identify models. Across 16 mainstream models, the method correctly identifies all 155 economically motivated model substitutions, with no false positives among the self-reference controls. In real-world audits, KBF finds inconsistency on 7 of 28 endpoints across six third-party routers. For text watermarking, we present SAMark, which anchors watermarks in sentence semantics independently of sentence order, achieving 88.1% detection at a 1% false-positive rate under extensive paragraph paraphrasing in experiment settings. In the end, we will discuss the remaining challenges and future directions.

Programmability ≠ Ease of Programming: Architecture Design and Kernel Development Agent (KDA) Co-Evolution in the Token-Maxxing Era

The Agent era is reshaping computer architecture across research significance, goals, and methods. This talk addresses how and what we should study in computer architecture when tokens are nearly unlimited, drawing on the PF-LLM and MoP projects to explore AI-generated code hints for CPU design, AI-assisted architectural exploration, and the distinction between programmability and ease of programming. We argue that programmability does not equal ease of programming. As Agents and vibe coding lower the barrier to writing code, architecture should prioritize hardware efficiency and performance optimization over traditional programmer usability, enabling more aggressive designs that were previously impractical due to programming complexity. In this setting, we examine the co-evolution of Kernel Development Agents (KDA) and system architecture, where the programming model and the hardware evolve together rather than the architecture being constrained by a fixed, human-oriented programming interface.
